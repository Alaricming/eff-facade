# Workbench 交互设计

## 1. 定位

Workbench 是 AI Facade 的主使用界面。

它不是悬浮聊天气泡，而是一个能够承载会话、生成式 UI、任务历史和调试信息的主工作区。

## 2. MVP 布局

MVP 采用三部分结构：

```text
┌────────────┬──────────────────────────────┬──────────────────────┐
│ 左侧工具栏 │ 中间主会话区                 │ 右侧 Drawer           │
│ Toolbar    │ Conversation                 │ 可通过按钮打开/关闭   │
└────────────┴──────────────────────────────┴──────────────────────┘
```

### 2.1 左侧工具栏

左侧工具栏用于承载高频入口。

左侧工具栏以 icon 为主，hover 时通过 tooltip 展示说明。

MVP 建议包含：

- 新建会话。
- 任务历史。
- 调试面板入口。
- 设置入口。

### 2.2 中间主会话区

主会话区是核心工作区。

特点：

- 从上到下的会话流。
- 用户输入、模型回复、Skill 结果、生成式 UI 都混在同一条消息流中。
- Skill 命中后的结果以消息卡片形式展示。
- 表单、确认卡片、查询结果、跳转链接都作为消息内容出现。

### 2.3 右侧 Drawer

右侧 Drawer 默认收起，通过按钮打开。

MVP 中 Drawer 用于承载：

- 任务历史。
- 调试信息。
- 后续设置、上下文、详情信息。

Drawer 可以根据入口切换不同内容。

## 3. 消息形态

MVP 消息类型：

- 用户文本消息。
- 普通问答文本消息。
- 运行中状态消息。
- 确认卡片消息。
- 表单卡片消息。
- 查询结果卡片消息。
- 跳转链接卡片消息。
- 自定义组件消息。
- 错误消息。

视觉风格上，普通文本更接近宽松气泡，结构化内容更接近轻量消息卡片。

## 4. Skill 结果展示

用户输入命中 Skill 后，结果在主会话区以消息卡片展示。

不在 MVP 阶段引入独立任务面板。

示例：

```text
用户：创建一个字典 storage_level，枚举值为：充足 1，紧张 2，空 3

AI：我识别到你要创建业务字典，请确认以下内容。

[确认卡片]
字典编码：storage_level
枚举项：充足=1，紧张=2，空=3
[取消] [确认创建]
```

## 5. 任务历史

MVP 需要任务历史。

任务历史记录用户触发过的业务任务，而不是所有普通聊天消息。

建议记录：

- 任务 ID。
- 用户输入。
- 命中的 Skill。
- 调用的原子能力。
- 任务状态。
- 创建时间。
- 更新时间。
- 关键结果摘要。

任务状态：

- `pending`
- `running`
- `waiting_user_input`
- `done`
- `error`
- `cancelled`

任务历史可以在右侧 Drawer 中查看。

## 6. 调试面板

MVP 需要调试信息面板，便于验证 Runtime、Skill 识别和模型提参是否正确。

调试面板放在右侧 Drawer 中。

建议展示：

- 用户原始输入。
- Skill recall 候选列表。
- 最终命中的 Skill。
- 命中的原子能力。
- 模型提取参数。
- 原子能力输入。
- 原子能力返回结果。
- 渲染结果类型。
- 错误信息。
- 阶段时间线。

阶段时间线用于快速解释一次运行过程：

- 接收输入。
- 召回候选 Skill。
- 模型完成意图识别。
- 调用原子能力。
- 返回并渲染结果。
- 失败时展示错误阶段。

调试面板默认仅作为开发/演示能力，后续公司级上线时需要受权限控制。

## 7. 输入区

MVP 输入区位于主会话区底部。

支持：

- 文本输入。
- 回车发送。
- 空输入禁用。
- 发送中状态。

第一版暂不支持：

- 文件上传。
- 语音输入。
- 多轮上下文补参。
- 富文本输入。

## 8. MVP 不做

- 独立任务详情页面。
- 多标签任务工作区。
- 可拖拽布局。
- 多会话并行。
- 文件上传。
- 复杂审批流。
