# 安全与治理待办

## 1. MVP 决策

第一版用于验证 AI Facade Runtime、Skill 协议和 Schema UI 能力，暂不接入真实公司级安全治理体系。

MVP 阶段：

- 不接入真实 SSO。
- 使用 Mock User Context。
- 暂不实现权限判断。
- 暂不实现字段级脱敏。
- 暂不实现完整审计日志。
- 写操作必须二次确认。
- 查询操作默认不需要确认。

## 2. 后续必须补齐的公司级能力

### 2.1 SSO 与身份上下文

后续需要通过 Auth Adapter 接入真实 SSO，并向 Facade Runtime 和 Skill 原子能力提供：

- 用户 ID。
- 用户名称。
- 组织信息。
- 角色信息。
- 登录态 Token。
- 租户信息。

### 2.2 权限判断

后续需要通过 Permission Adapter 支持：

- Skill 级权限。
- API 级权限。
- 操作级权限。
- 字段级权限。
- 跨系统权限透传。

### 2.3 字段脱敏

后续需要对敏感字段进行展示控制，例如：

- 手机号。
- 邮箱。
- 证件号。
- 地址。
- 用户身份信息。
- 业务敏感配置。

### 2.4 审计日志

后续至少需要记录：

- 用户是谁。
- 输入了什么。
- 命中了哪个 Skill。
- 调用了哪个 API。
- 提交了哪些关键参数。
- 结果成功还是失败。
- 失败原因。
- 操作时间。

### 2.5 风险分级

后续 Skill 需要声明风险等级：

- `low`：查询、普通问答。
- `medium`：创建、修改低风险配置。
- `high`：删除、批量修改、影响核心业务流程。

不同风险等级应对应不同确认、权限和审计策略。

### 2.6 Server-side Executor

后续需要支持公司级服务端执行器：

- 原子能力可选择在服务端运行。
- 服务端统一处理鉴权。
- 服务端统一处理审计。
- 服务端统一处理敏感数据。
- 服务端负责跨系统调用和密钥管理。
